# 引き継ぎメモ：コンバットドリルの戦闘判断を Forge に移植する

新しいチャットでは、まずこのメモを読んでから着手してください。

## 1. ゴール

コンバットドリルで使っている「全パターン探索で最善の攻撃を求める」戦闘判断を、MTG のオープンソースエンジン **Forge** の AI に組み込む。そのうえで AI 同士の自己対戦（画面なしの sim モード）を回し、元の AI との勝率を比べる。

- 移植先：ユーザーがフォークした Forge（`meatgoodbyeeee-wq/forge` の予定。名前はユーザーに確認）
- 元ネタ：このリポジトリ（`meatgoodbyeeee-wq/combat-drill`）の `src/`
- 公開中のアプリ：https://meatgoodbyeeee-wq.github.io/combat-drill/

## 2. コンバットドリルのエンジン構成（`src/`）

| ファイル | 内容 |
|---|---|
| `engine.js` | **基本エンジン**（手札なし・盤面だけ）。クリーチャーをビットマスクで持つミニマックス＋αβ枝刈り＋置換表 |
| `engine2.js` | **インスタント用エンジン**（公開手札・優先権・スタック・手札クリーチャー）。基本エンジンを内部に埋め込み、手札が尽きたら切り替える |
| `test/unit.js` `test/unit2.js` | ルールの単体テスト（`node test/unit2.js`） |
| `test/xcheck.js` | 手札なしの盤面で両エンジンの評価値が一致するかのランダム照合 |
| `template4.html` ほか | 画面。`python3 build.py` で `hosted/index.html` を作り、リポジトリ直下の `index.html` にコピーして公開 |
| `bank.js` `bank/*.jsonl` | 読みモードの同梱問題の生成スクリプトと生成済み問題 |

### 戦闘の共通処理（両エンジン共通、`engine.js` 冒頭）

- `ccCombat(att, blk)`：攻撃クリーチャーとブロッカーを受け取り、起こりうる戦闘結果をすべて返す（攻撃側のダメージ割り振りの選択肢ごと）。結果は生死・本体へのダメージ・絆魂の回復量など
- `ccAssign`：ダメージ割り振りの候補。現行ルール（ファウンデーションズ以降）で、攻撃側が自由に割り振れる。候補は「倒せる組み合わせの極大集合＋余りを1体に」。トランプルは致死ぶんを割り振った残りを本体へ
- `ccDeals`：先制攻撃ステップと通常ステップ（二段攻撃は両方）
- `ccValue`：盤面評価用のクリーチャー価値（6×パワー＋4×タフネス＋キーワード加点）

### 探索（`engine.js` の `makeSolver`）

- 手番：攻撃宣言（攻撃クリーチャーの部分集合）→ ブロック（威迫・飛行／到達を考慮した全割り当て）→ 戦闘結果 → 相手のターン、を交互に読む
- 評価値：勝ち＝1000−手数、負け＝−1000＋手数。読み切れなければ、ライフ差とクリーチャー価値の差による評価
- 最大読み手数（`maxPly`）は難易度ごとに 6〜10（3〜5往復）
- 攻撃したクリーチャーはタップし（警戒は除く）、相手のターンにはブロックできない。このテンポの読みが判断の核

### モデル化しているルール

- キーワード：飛行・到達・先制攻撃・二段攻撃・接死・トランプル・威迫・警戒・絆魂・破壊不能・防衛・呪禁・護法（{1}/{2}）・速攻・瞬速
- インスタント：『ファウンデーションズ』の15種（`engine2.js` の `CARDS`）。優先権を w1（戦闘前メイン）〜w4（ダメージ後・終了時）の窓に絞って探索
- **扱っていないもの**：プロテクション、起動型・誘発型能力全般、+1/+1カウンター以外の継続効果、ドロー、土地以外のマナ源、色の制約（マナは土地の枚数だけで判断）

## 3. 移植の方針案（着手時にユーザーと確認）

### 対象

Forge の AI の戦闘判断は主に次のクラスにある（**パスは着手時に要確認**）。
- 攻撃：`forge-ai/src/main/java/forge/ai/AiAttackController.java`
- ブロック：`forge-ai/src/main/java/forge/ai/AiBlockController.java`
- 戦闘の予測：`forge-ai/src/main/java/forge/ai/ComputerUtilCombat.java`

### 進め方の案

1. **Java への移植**：`ccCombat`／`ccAssign`／`makeSolver`（基本エンジン）を Java に移す。まずは手札を考えない基本エンジンだけでよい
2. **変換層**：Forge の盤面（`Card` の P/T・キーワード・タップ状態・召喚酔い、プレイヤーのライフ）を、ドリルのクリーチャー形式 `{p, t, fly, reach, fs, ds, dt, tr, me, vg, ll, ind, df}` に変換する
3. **適用範囲**：盤面のクリーチャーが全員「モデル化しているキーワードだけ」のときに限って探索の結論を使う。それ以外（起動型能力持ちなど）は Forge の元の判断に任せる
4. **時間制限**：1回の判断に上限時間を設ける（ドリルでは 3体対3体程度なら数十ms〜数秒）。超えたら元の判断に戻す
5. **攻撃から**：まず攻撃宣言だけ差し替える。ブロックの差し替えは効果を見てから
6. **比較**：同じデッキの対戦で「元のAI 対 移植AI」を先手・後手を入れ替えて回し、勝率を比べる。最初は能力の少ないクリーチャー中心のデッキ（ファウンデーションズのリミテッド風）が効果を見やすい

### 自己対戦（sim モード）

Forge には画面なしで AI 同士を対戦させるモードがある（例：`forge sim -d デッキ1 デッキ2 -n 試合数 -q`。**正確なコマンドとデッキファイルの置き場所は着手時に要確認**）。

## 4. 作業環境の注意

- このアプリの作業環境は CPU 2コア・メモリ 8GB 程度。Forge のビルドは Maven（Java）。依存の取得は Maven Central から可能な見込みだが、着手時に確認
- 返信が終わると、裏で動かしているプロセスは数分で止まる。数千試合規模の自己対戦は、何回かに分けて回す
- Forge は **GPL-3.0**。フォーク内に書いたコードも GPL になる（コンバットドリル本体の公開には影響しない）
- コミット・プッシュはユーザーの指示があるときだけ

## 5. 経緯メモ

- コンバットドリルは2026年11月時点で、基本・インスタント・読みの3モード×3難易度。「むずかしい」の最高連続正解数を Firebase（Googleログイン）でランキング
- 移植は「キーワード能力を増やしてから」というユーザーの判断で後回しにしていた。キーワード追加が完了したので、次の作業が移植
